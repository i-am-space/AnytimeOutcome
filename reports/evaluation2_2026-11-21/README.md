# Evaluation 2: implementation, results and learning package

Start with **Evaluation2_Learning_Guide.pdf**, page 2. It offers a two-hour route, a four-hour route and an eight-hour route through the same 45-page guide. Pages 41–45 contain 25 evaluation questions with answers.

**Evaluation2_Presentation.pdf** is the presentation-ready deck. **Evaluation2_Presentation.pptx** contains editable text/shapes, embedded plots and native speaker notes. Slides 1–11 total ten minutes; slides 12–21 are Q&A backups. **Evaluation2_Speaker_and_QA_Guide.pdf** contains the timed scripts, technical follow-ups, transitions, rubric mapping and questions.

The data cutoff is recorded in evidence_manifest.json. The partial unequal-depth study is 43/60 valid held-out blocks at that cutoff. The newest greedy handoff version has not run its GPU tests or measurements. Later results do not silently change these artifacts.

## Main conclusion

We built safe incremental publication and compacted unequal-depth drafting. The completed publication study is about 1% slower than tuned complete K7 SSD. Context diagnostics show a same-K10 benefit but no advantage over complete K7. Unequal-depth test results are provisional and slower. Established SSD acceleration versus AR is a baseline result, not an incremental speedup achieved by our scheduler.

Exact-output claims concern **shared-fixed16-v1 AR**. The original AR numerical implementation remains a separate control; shared AR differed on seven of nine diagnosed prompts. The initial paired shared gate passed while its historical-original-AR reproduction gate failed. Stale generic headings in the old baseline generator are preserved as historical evidence, but this package rechecks actual token sequences.

## Evidence and reproducibility

- evidence_manifest.json: frozen source paths, hashes and cutoff.
- block_audit.json: primary accepted receipt inventory; failed/incomplete blocks do not count.
- historical_audit.json: additional older completed-study receipts, including the explicitly reused v1 uniform-depth tuning source. Shared-GPU engineering gates are not performance evidence.
- analysis.json: direct token comparisons and balanced partial-study statistics, using the archived 10,000-sample paired-bootstrap function.
- figure_data.json, figure_values.csv, experiment_tables.csv: full plotted values and complete tuning/aggregate tables.
- figure_manifest.json: chart sources and interpretation boundaries.
- artifact_validation.json: PDF rendering, geometry, numerical, source-hash and PowerPoint structure/notes checks.
- source_documents/Project_Proposal.pdf and rubric.json: proposal and evaluation requirements used for the remaining-plan and rubric mapping.
- validation_logs/: independent CPU test invocations, not an additive test total.

The unpacked evidence_snapshot is excluded from Git to avoid duplicating raw experiment records. It is included in **Evaluation2_Package.zip**, alongside the documents, figures, sources and builders. Extract that archive to reproduce the package without accessing the original running experiment directories.

With the packages in requirements-docs.txt available, run these from the extracted directory:

```bash
python make_figures.py
python build_package.py
python validate_artifacts.py
```

These builders use saved evidence only. They do not launch GPU experiments, modify the baseline, or retune on test results. The host has no native Office renderer: the PowerPoint passes XML/relationship/notes validation and shares scene geometry with the visually checked PDF. Full-resolution PDF page previews can be regenerated by validate_artifacts.py.
